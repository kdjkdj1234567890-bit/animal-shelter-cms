## 실행 방법

```bash
cd ~/workspace/animal-shelter-demo
bash run.sh        # 또는 python3 app.py
```

- 공개 홈페이지: http://localhost:8080
- 관리자(CMS): http://localhost:8080/admin → 로그인 페이지로 이동
- **데모 계정: `admin` / `demo1234`** (로그인 화면에 표시됨)
- Python 3 + Flask + SQLite + Pillow (별도 DB 설치 불필요)
- 첫 실행 시 샘플 데이터 자동 생성: 동물 8마리, 입양 신청 2건, 소식 3건(비공개 1건 포함), 봉사 신청 0건, 301 규칙 3건, 진료 기록 4건, 입양 후기 1건
- 초기화: `data/` 폴더 삭제 후 재실행

## 새로 추가된 시연 포인트 (v3)

### A. 저장 전 미리보기 (CMS)
- 개체 등록/수정 폼 → **"👁️ 저장 전 미리보기"** 버튼 → 새 창에 방문자 화면 그대로 표시 (미리보기 배너 포함)
- 소식 쓰기에도 동일 기능. "발행 전에 어떻게 보이는지" 불안 해소

### B. 일괄 작업 (CMS)
- 개체 관리 목록 → 체크박스 선택 → **상태 일괄 변경 / 일괄 삭제** (확인 창 포함)

### C. 변경 이력 (CMS)
- 관리자 → **변경 이력** 메뉴: 모든 관리자 작업(등록·수정·삭제·승인·가져오기)이 일시·내용과 함께 자동 기록

### D. 진료 기록 + 갤러리 + 입양 후기 (개체 관리)
- 개체 수정 화면에서 **진료·예방접종 기록** 추가/삭제 → 공개 상세 페이지 "🏥 건강 기록"에 표시
- **사진 갤러리**: 여러 장 한 번에 업로드 → 공개 상세에 갤러리로 표시
- 관리자 → **입양 후기** 메뉴에서 후기 등록 → 공개 `/reviews` 페이지에 표시

### E. CSV 일괄 가져오기 (데이터 이전)
- 관리자 → **가져오기** 메뉴 → 양식 다운로드 → 엑셀에서 CSV로 저장 → 업로드
- 결과 리포트 (등록 N건 / 제외 M건 + 사유)
- 스크립트 방식: `python3 scripts/migrate_cafe24.py --dry-run` (DB 변경 없이 변환 결과 확인)
- **이미지 자동 이전**: `python3 scripts/migrate_cafe24.py --apply --images` — 구 시스템 이미지 URL(wr_6)을 자동 다운로드 → WebP/AVIF 최적화 → DB 연결 (실측: 2건 성공)

### F. WYSIWYG 서식 편집기 + 소식 수정 (CMS)
- 소식 쓰기 → **서식 있는 편집기**: 굵게·기울임·밑줄·제목·목록·링크·**사진 삽입(업로드 시 WebP 자동 최적화, 용량 표시)**
- 서버에서 allowlist 기반 HTML 정화 (script·onerror·javascript:·외부 이미지 차단 — XSS 테스트 통과)
- 소식 관리 → **수정** 버튼 → 기존 내용 그대로 편집기에 로드

### G. 이미지 고도화 (트래픽)
- 업로드 시 **AVIF 추가 생성** (WebP 대비 9~22% 추가 절감, 지원 브라우저에서 `<picture>`로 자동 선택)
- **blur-up 플레이스홀더**: 20px 블러 이미지를 base64로 인라인 → 로딩 체감 속도 개선
- 대표 사진·갤러리 모두 적용, 삭제 시 AVIF 파일까지 함께 정리

### H. 대시보드 시각화 + SEO (신뢰도)
- 관리자 대시보드 → **🍩 상태별 분포 도넛 차트** (CSS conic-gradient, 외부 라이브러리 없음) + **⚡ 오늘의 할 일** (대기 신청 바로가기)
- 홈페이지 **JSON-LD 구조화 데이터** (schema.org NGO) — 검색 노출 기반

## 시연 시나리오 (의뢰인에게 보여줄 순서, 약 10분)

### 1. "링크만 알면 열리는 비공개 글" 문제 해결 (공고 명시 pain)
1. 비로그인 상태에서 `/admin` 접속 → 로그인 화면으로 이동됨을 확인
2. 로그인 후 소식 관리 → `[내부] 11월 이사회 안건 초안` 글이 **🔒 비공개** 표시
3. 새 창(비로그인)에서 `/notices/3` 직접 입력 → **404** (링크를 알아도 열 수 없음)
4. 개체 관리 → 초코 → **🔒 비공개 메모** (치료비 협의 내용, 관리자만 열람)

→ "지금 겪고 계신 비공개 글 노출 문제를 권한 확인 구조로 막는 방식입니다"

### 2. 사진 업로드 → 자동 최적화 (트래픽 pain)
1. 개체 등록 → 큰 사진 파일 업로드 후 저장
2. 목록에 **`14.5KB → 1.8KB`** 같은 최적화 배지 표시 확인 (실측 예시, 약 87% 감소)
3. 공개 상세 페이지에서 변환된 WebP 이미지가 표시됨

→ "봉사자가 올리는 원본 사진이 그대로 나가서 트래픽 초과가 났던 구조를, 업로드 시점에 자동 최적화하는 방식으로 바꿉니다. 정식 구축 시에는 CDN 앞단 배치로 완성합니다"

### 3. 운영 자동화 (핵심 킬러 시연)
1. 공개 페이지에서 아무 동물이나 **입양 신청하기** → 신청서 작성·제출
2. 관리자 → 입양 신청 → 검토하기 → **✅ 승인** 클릭
3. 개체 상태가 자동으로 **입양완료**로 변경 + 대기 중이던 다른 신청 **자동 마감**(거절 + 사유 메모)
4. 공개 페이지에서 해당 동물의 신청 버튼이 사라지고 완료 배지 표시

→ "상태 바꿀 때마다 손으로 챙겨야 했던 일(신청 버튼 숨김, 완료 표시, 변경일 기록, 중복 신청 정리)이 전부 자동으로 됩니다"

### 4. 301 리디렉션 (데이터 이전)
1. 관리자 → **URL 이전** 메뉴 → 등록된 구 URL → 신규 URL 맵 확인
2. 브라우저에 `/board/notice` 입력 → `/notices`로 **301 이동** 확인
3. 새 규칙 등록 시연 (예: `/old-event` → `/notices`)

→ "기존 카페24 주소를 새 주소로 영구 이전해서 검색 순위와 공유 링크가 끊어지지 않습니다"

### 5. 쉬운 CMS (비개발자 관점)
- 개체 등록 폼: 종·성별·상태는 **드롭다운**, 구조일은 **달력 선택**, 나머지는 짧은 입력칸
- 상태 변경: 목록에서 드롭다운으로 바꾸고 "변경" 클릭 한 번 → 변경일 자동 기록

## 보안 (데모 범위 내 적용)

| 항목 | 조치 |
|---|---|
| 인증 | 관리자 전체 `/admin/*` 세션 로그인 필수 (정식: DB 계정 + bcrypt + 역할 분리) |
| 인가 | 비공개 글/메모는 로그인 사용자만 조회, 공개 라우트에서 404 처리 |
| CSRF | 전 POST 폼에 세션 기반 토큰 검증 |
| XSS | Jinja2 자동 이스케이프 (템플릿 내 `\|safe` 미사용) |
| SQL 인젝션 | 전 쿼리 파라미터 바인딩 |
| 파일 업로드 | 확장자 화이트리스트(jpg/png/webp), 10MB 제한, 랜덤 파일명, WebP 재인코딩 |

## 정식 구축 시 기술 스택 제안

| 구분 | 데모 | 정식 구축 |
|---|---|---|
| 백엔드 | Flask | **Spring Boot + JPA** (동일 비즈니스 로직 이식, `src/` 스켈레톤 포함) |
| DB | SQLite | MySQL / PostgreSQL |
| 인증 | 단일 계정 | DB 계정 + bcrypt + 역할(관리자/운영진) 분리 |
| 이미지 | 로컬 WebP 변환 | 업로드 시 WebP 변환 + **CDN**(Cloudflare) + 지연 로딩 |
| 트래픽 | — | 페이지 캐시, 일 백업·스냅샷 복구 절차 |
| 배포 | 로컬 | 클라우드 VM + HTTPS, 도메인 연결 |

> 참고: 당초 Spring Boot로 구축하려 했으나 현재 환경에서 Maven Central 접속이 차단되어 빌드 불가 → 동일 기능을 Flask로 구현했습니다. 실제 수주 시 Spring Boot + JPA로 정식 구축하며, 데모에서 검증된 비즈니스 로직(자동 규칙·권한 구조)은 그대로 이식됩니다.
